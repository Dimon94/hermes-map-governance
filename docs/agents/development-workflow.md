# Development Workflow

用途：约束功能开发、缺陷修复、重构和交付。主词是证据闭环。

## 1. 定义目标

记录用户现象、可观察结果、范围和不变量。

- 根因未知时，保持方案中立。
- 验收标准只写外部可观察结果和必须保持的合同。
- 实现猜想放入调查记录，不写成需求。

完成标准：任务可独立验证；未知项明确标为 Unknown。

## 2. 锁定基线

读取目标文件最近的 AGENTS.md、CONTEXT.md、System Map、直接调用者、公开入口、相关测试和配置。

记录：

- 当前分支和工作区状态。
- 最小现有测试的结果。
- 相关运行证据或复现输入。
- 用户已有的无关修改。

完成标准：知道哪项现有行为将作为对照，且不会覆盖无关改动。

## 3. 设计最小切片

按以下顺序寻找实现：

1. 最近的 canonical owner 和已有 public interface。
2. 同目录 helper、type、schema、错误和测试模式。
3. 标准库、运行时原生能力和已安装依赖。
4. 只有前三层不适用时，新增最少实体。

若改变所有权、依赖方向、公开合同或持久状态，先读 Architecture Standards 和 Layer Contracts。难回退决定先写 ADR。

完成标准：每个新增实体都有当前职责；不存在平行机制。

## 4. 留下失败检查

功能开发先写能区分完成与未完成的检查。缺陷修复用同一输入复现问题。

优先级：

1. 最近 public interface 的 focused test。
2. 边界 adapter 的合同测试。
3. 最小可复跑的 assert 或命令。
4. 关键真实路径的 smoke test。

完成标准：错误实现会失败；检查不依赖私有实现细节。

## 5. 实现

修改 canonical owner。保持 adapter 薄。把副作用集中到明确写入者。

- 输入在 seam 校验。
- 内部使用 typed value。
- 失败语义稳定且可测试。
- 并发、重试、幂等和恢复由 owner 表达。
- 不添加当前需求之外的配置、fallback 或扩展点。

完成标准：最小检查通过，原有边界保持成立。

## 6. 验证

按风险逐层运行：

1. focused test。
2. 受影响模块测试。
3. 类型检查、lint 或语法检查。
4. build。
5. 必要时走真实公开入口。

真实入口同时断言 transport 和业务结果。HTTP 2xx、进程存活或文件存在不能单独证明成功。

完成标准：验证命令可复跑；结果与需求和不变量一致。

## 7. 文档回环

按 Layer Contracts 列出当前变更命中的 L1-L6 触发面。更新对应 canonical 文档。

- 统一语言变化：CONTEXT.md。
- 顶层所有权或依赖变化：System Map。
- 难回退决定：ADR。
- 模块成员或入口变化：最近 AGENTS.md。
- 公开参数和流程约束：最近代码合同或专用合同文档。

完成标准：文档描述当前事实，不描述尚未落地的愿景。

## 8. 收口

运行 git diff --check，并检查工作区。

交付说明包含：

- 触达坐标。
- 实际改动。
- 验证命令和结果。
- 跳过项与剩余风险。

只有用户明确要求时才 stage、commit、push、创建 PR 或部署。Stage 时列出具体路径。
